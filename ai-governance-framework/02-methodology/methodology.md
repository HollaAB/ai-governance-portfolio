# Methodology: AI Governance Framework

Draft 0.1, prepared for review by Abel Holla.

1. **Inventory.** Ask every department and supplier which tools use AI (including features inside vendor software) and record them in the [AI system inventory](../03-ai-inventory/ai-system-inventory.csv).
2. **Classify.** Score each use case against the criteria in the [classification method](../04-classification/ai-risk-classification-method.md) and record the tier.
3. **Assess.** For each high-risk system, complete an AI impact assessment alongside the DPIA.
4. **Test.** Run a written test protocol before approval and after every significant change; record results.
5. **Assign oversight.** For each system, name the owner and the human who reviews or overrides outputs, in the [human oversight matrix](../06-oversight/human-oversight-matrix.csv).
6. **Check vendors.** Score AI vendors with the [due diligence checklist](../07-third-party/vendor-ai-due-diligence-checklist.csv).
7. **Monitor.** Record model changes and AI incidents; report quarterly.

## Reference frameworks

The structure follows the NIST AI Risk Management Framework 1.0 functions (Govern, Map, Measure, Manage) and the management system approach of ISO/IEC 42001:2023. Kenya's National AI Strategy 2025 to 2030 (to verify) and the Data Protection Act 2019, including s.35 on automated decisions (to verify), set the local context. Using these frameworks does not mean the Club or this project is certified against them.
